# Pipa 多数据库开发者工作台产品设计

- 状态：已确认
- 日期：2026-07-12
- 产品形态：Windows、macOS、Linux 跨平台桌面客户端
- 核心技术：Tauri + Rust 核心 + React/TypeScript 界面
- 数据策略：全部本地存储

## 1. 执行摘要

Pipa 是一款面向开发者和数据工程师的本地优先、多数据库桌面工作台。它在一个轻量、统一的界面中支持 MySQL、PostgreSQL、MongoDB 和 Redis 的连接、对象浏览、查询、数据修改、结构查看、调试与导入导出，同时保留每种数据库的原生查询语言和开发能力。

产品采用“统一外壳 + 原生数据库适配器”路线。连接、工作区、标签、快捷键、结果操作、安全规则和后台任务保持一致；SQL、MongoDB Query/Aggregation Pipeline 和 Redis Commands 不被抽象成所谓“万能查询语言”。

Pipa 的差异化不是堆叠最多功能，而是在四类数据库之间提供简单、高效、可预测的操作体验，并将性能、数据管理、快捷操作和交互质量作为首版验收条件。

## 3. 市场对标与机会

### 3.1 对标产品

- [DBeaver](https://dbeaver.com/features/)：数据库覆盖面广，提供 SQL 编辑、元数据浏览、ER 图和数据迁移等完整能力。优势是全能，代价是信息密度和操作复杂度较高。
- [DataGrip](https://www.jetbrains.com/datagrip/features/)：SQL 编写、Schema 感知、搜索、执行分析和开发工具整合能力强，适合作为专业 SQL 开发体验参考。
- [TablePlus](https://docs.tableplus.com/)：强调原生、快速和简洁的多数据库体验，可作为轻量桌面交互参考。
- [Navicat Premium](https://www.navicat.com/en/products/navicat-premium.html)：在单一产品中覆盖 MySQL、PostgreSQL、MongoDB 和 Redis，并提供数据编辑、迁移、建模和同步等大量能力，可作为功能广度参考。
- [MongoDB Compass](https://www.mongodb.com/products/tools/compass/features)：MongoDB 查询、聚合管道、Schema 分析、索引和 Explain 的原生体验是 MongoDB 适配器的重要参考。
- [Redis Insight](https://redis.io/docs/latest/develop/tools/insight/)：Redis 数据结构浏览、Workbench、格式化和诊断能力是 Redis 适配器的重要参考。

### 3.2 产品机会

市场产品通常在“覆盖广但界面重”“界面轻但数据库深度不一致”“单库原生体验强但需要切换多个软件”之间取舍。Pipa 的机会是：

1. 用固定的界面结构和操作语法降低跨数据库切换成本。
2. 用独立适配器保留 MongoDB 与 Redis 的原生能力，而不是强行 SQL 化。
3. 用 Rust 后台、流式结果和虚拟化表格控制启动速度、内存与大数据量体验。
4. 用明确的连接分区、上下文锁定和生产环境保护减少误操作。

以上机会判断是基于官方功能资料作出的产品推断，不代表对竞品质量的绝对评价。

## 4. 目标用户与核心场景

### 4.1 目标用户

主要用户是需要在多个数据库之间高频切换的后端开发者、全栈开发者和数据工程师。他们熟悉查询语言，但不希望为了不同数据库维护多套客户端与操作习惯。

### 4.2 核心场景

1. 在本地、测试和生产连接之间快速切换并执行查询。
2. 浏览表、集合或 Redis 键，定位数据问题。
3. 查看关系型表结构、索引、约束和完整 DDL。
4. 修改少量数据，预览差异后安全提交。
5. 分析 SQL 执行计划、MongoDB 聚合管道或 Redis 数据结构。
6. 复制行、列、单元格或查询结果，并导出为常见格式。
7. 查询耗时较长或导出大量数据时继续处理其他任务。

## 5. 产品原则

1. **统一操作，不统一查询语言。** 共享导航、标签、快捷键和结果动作；保留数据库原生语义。
2. **简单、高效。** 高频操作最多两次操作可达，常规流程不超过三层导航，每个界面最多一个突出主操作。
3. **上下文永远可见。** 查询标签持续展示数据库类型、连接、库、Schema 和环境；切换对象树不会修改已打开查询的绑定。
4. **本地优先。** 不要求账号，不上传连接、查询、Schema 或使用数据。
5. **安全默认开启。** 浏览和复制不增加打扰，危险写操作按环境和影响范围提升确认等级。
6. **渐进披露。** 默认只展示连接、浏览、查询、编辑和导出；高级能力在相关对象或详情中按需出现。
7. **可恢复。** 崩溃或关闭后恢复工作区、未保存查询、标签和布局，但不默认永久保存查询结果。

## 6. 产品范围

### 6.1 首版包含

- 四种数据库的连接、对象浏览、查询、编辑、导入导出和原生开发能力。
- SSH 隧道、SSL/TLS、连接健康检测与环境标记。
- 查询历史、收藏、模板、工作区恢复和全局命令面板。
- SQL 事务、执行计划、索引、表结构和 DDL。
- MongoDB 文档、聚合管道、Schema 分析、验证规则和索引。
- Redis 常见数据结构、TTL、命令工作台、Pub/Sub 和慢查询日志。
- 本地后台任务、生产环境保护、敏感数据遮蔽和诊断信息。

### 6.2 首版不包含

- 团队云同步、多人协作或组织权限。
- AI 查询生成或自动修复。
- 备份恢复、用户权限管理和服务器运维等 DBA 套件。
- 第三方插件市场。
- 跨数据库联邦查询或统一查询 DSL。
- Web 版与移动端。

## 7. 信息架构与主界面

主界面采用已确认的混合工作台：

1. **窄功能栏**：连接、全局搜索、收藏、历史、任务和设置。
2. **数据库导航区**：MySQL、PostgreSQL、MongoDB、Redis 使用独立分区卡片；连接只能出现在所属引擎内；对象继续缩进在连接下。
3. **中央标签区**：查询、对象详情、数据视图和工具页面使用统一标签体系。
4. **结果区**：表格、JSON、执行计划和消息等视图位于中央区域下方，可调整高度或最大化。

数据库引擎、连接和对象形成三层视觉权重。颜色只用于辅助识别，核心边界由标题、卡片、边框、缩进和留白保证。

## 8. 交互规范

### 8.1 选择与打开

- 可选择行的最小高度为 40px，文字、图标和空白区域均可点击。
- 悬停、键盘焦点与选中使用不同状态。
- 选中状态同时使用底色、描边、左侧标记、勾选和环境标签，不只依赖颜色。
- 单击对象进行临时预览；双击或点击固定按钮保留标签。
- 点击其他连接只改变左侧浏览目标，不修改已有查询标签的数据库上下文。

### 8.2 固定操作语法

| 操作 | 快捷键 |
| --- | --- |
| 全局命令面板 | `Ctrl/Cmd + K` |
| 执行当前语句或选中内容 | `Ctrl/Cmd + R` |
| 在当前连接中新建查询 | `Ctrl/Cmd + T` |
| 快速打开数据库对象 | `Ctrl/Cmd + P` |
| 导出当前结果 | `Ctrl/Cmd + Shift + E` |
| 重命名当前对象 | `F2` |

应用覆盖 `Ctrl/Cmd + R` 的常见刷新含义；刷新 WebView 仅保留在开发调试模式。所有快捷键可在设置中自定义。右键菜单和命令面板使用同一个命令注册表，避免能力不一致。

### 8.3 Loading

Loading 只用于表达“操作正在进行”，不承担诊断或统计信息：

- 查询：小型动效 + “查询中…” + 必要的取消入口。
- 流式结果：结果底部显示“正在加载更多…”。
- 后台导出：任务中心显示“正在导出…” + 必要的取消入口。
- Loading 就近显示，不遮挡整个窗口；完成后立即移除。
- 耗时、阶段、处理行数和技术信息不出现在 Loading 中。
- 失败信息属于错误反馈，不与 Loading 同时堆叠。

### 8.4 修改与结构变更

- 数据编辑先写入本地 Change Set，不立即提交数据库。
- 待提交区展示旧值、新值、目标环境和预计影响范围。
- 用户可提交单项、全部提交或全部撤销。
- 关系型表结构修改通过结构编辑器完成，执行前展示生成的原生 DDL。
- MongoDB 文档和 Redis 键值使用适合其数据结构的编辑器，不套用关系型表单。

## 9. 共享功能

### 9.1 连接管理

- 按数据库引擎严格分区。
- 支持连接测试、自动重连、SSH 隧道、SSL/TLS 和超时配置。
- 连接标记为 Production、Development 或 Unspecified。
- 凭据保存在系统钥匙串，连接配置与凭据分离。

### 9.2 查询与结果

- 多标签查询编辑器、语法高亮、补全、格式化、语句切分和参数化查询。
- 查询取消、超时、历史、收藏、模板和执行错误定位。
- 表格与 JSON 结果视图；MongoDB 和 Redis 可提供数据类型专用视图。
- 分页或流式读取、虚拟化渲染、筛选、排序、列宽、列固定和全屏单元格查看。

### 9.3 数据快捷操作

- 复制单元格、行、列和矩形区域。
- 复制为纯文本、CSV、JSON、Markdown、SQL `INSERT` 或 `IN (...)`。
- 导出 CSV、JSON、SQL 和 Markdown。
- 关系型数据库支持 CSV 导入；MongoDB 支持 JSON/JSONL；Redis 支持适合具体数据结构的导入。
- 导入、导出与大批量数据操作在后台执行，不阻塞查询。

- 数据编辑、事务、Explain/Analyze 和执行统计。

- 批量删除或修改前显示影响范围并确认。

## 11. 系统架构

### 11.1 界面层

Tauri 承载 React/TypeScript 界面。界面层负责导航、编辑器、虚拟化结果表格、交互状态和可访问性，不直接持有数据库凭据或驱动连接。

### 11.2 Rust 应用核心

Rust 核心由以下高内聚模块组成：

- 连接管理：连接生命周期、连接池、重连、SSH/SSL 和健康检查。
- 查询调度：任务队列、取消令牌、超时、并发限制和流式结果。
- 元数据服务：对象树、能力描述、缓存和按需刷新。
- 数据任务：复制、导入、导出和临时文件管理。
- 安全策略：环境识别、危险操作分类、确认等级和日志脱敏。
- 本地资产：工作区、历史、收藏、模板、设置和恢复。

### 11.3 数据库适配器

每个适配器通过统一能力接口向核心声明并实现：连接、元数据、查询、取消、结果转换、数据修改、结构与 DDL、执行分析和导入导出。

适配器可以声明不支持的能力。核心与界面必须按能力显示功能，禁止展示不可执行的假入口。数据库特有能力保留在适配器内部，例如 MongoDB Pipeline 与 Redis TTL。

## 12. 数据流

### 12.1 查询

1. 标签携带不可隐式改变的连接、库、Schema 和环境上下文。
2. 界面通过 Tauri IPC 提交查询命令。
3. Rust 查询调度器验证上下文与安全策略，获取连接并创建取消令牌。
4. 数据库适配器使用原生驱动执行查询。
5. 结果分批返回界面，首批到达后立即显示。
6. 用户可继续拉取、暂停、取消或将完整结果转为后台导出。

### 12.2 数据修改

1. 界面修改写入本地 Change Set。
2. 提交前展示差异、目标环境和预计影响范围。
3. 适配器生成原生操作；SQL 尽量使用事务，MongoDB 按 `_id` 定位，Redis 使用明确的原子命令。
4. 提交成功后刷新受影响数据。
5. 发现冲突时保留本地修改并要求用户比较，不静默覆盖。

### 12.3 导出

导出从查询游标流式写入 `.part` 临时文件，完成后原子改名。取消、失败或崩溃恢复时清理未完成临时文件，避免生成看似完整的损坏结果。

## 13. 本地存储

| 存储位置 | 内容 |
| --- | --- |
| 系统钥匙串 | 数据库密码、SSH 私钥口令、令牌、本地 SQLite 加密密钥 |
| 加密 SQLite | 非秘密连接配置、工作区、历史、收藏、标签恢复、偏好、任务记录、元数据缓存 |
| 用户文件 | 主动保存的查询和导出文件 |
| 临时目录 | 流式缓存和未完成导出 |

查询结果默认不永久保存。未保存的查询文本自动恢复。查询历史默认保留 90 天，允许修改保留期限或关闭。日志不记录密码、令牌和完整数据值，并进行轮转。剪贴板只在用户主动复制时写入，不后台读取。

## 14. 安全与错误处理

### 14.1 生产环境保护

- 生产标记持续出现在连接树、查询标签和危险操作确认中。
- `SELECT`、浏览和复制不增加确认。
- `UPDATE`、`DELETE`、`DROP`、`TRUNCATE` 和批量 Redis 删除等操作按风险确认。
- 无条件更新或删除提高警告等级。
- 不支持统一事务的数据库按原生能力执行，不声称具备全局原子性。

### 14.2 错误反馈

错误被归类为连接、认证、权限、语法、冲突、资源、取消和内部错误。界面按三层呈现：

1. 发生了什么。
2. 用户下一步可以做什么。
3. 默认折叠的数据库原始错误与可复制诊断详情。

错误在任务所在区域显示。连接断开不清空编辑内容；写入冲突不丢弃 Change Set；取消查询保留已返回结果并标记其可能不完整。

## 15. 性能预算

以下指标在团队约定的基准设备与固定测试数据集上验收：

| 指标 | 首版目标 |
| --- | --- |
| 冷启动到可操作 | 不超过 2.5 秒 |
| 空闲内存 | 不超过 250 MB |
| 查询额外首批开销 | 排除数据库与网络时间后不超过 200 ms |
| 输入与点击反馈 | 不超过 100 ms |
| 结果表格滚动 | 目标 60 fps |
| 大结果集 | 不整批驻留内存，使用流式读取与虚拟化渲染 |

元数据树先展示缓存，再后台刷新。刷新过程中保留旧内容，避免界面跳空。耗时操作在 Rust 后台执行，不能阻塞窗口交互。

## 16. 视觉与可访问性

- 使用克制的专业工具风格、清晰排版、充足留白和轻量层次。
- 同时支持浅色和暗色模式。
- 数据库引擎颜色只作为辅助识别，不作为唯一状态信号。
- 每个可交互元素提供悬停、焦点、按下、选中和禁用状态。
- 键盘可完成连接选择、对象搜索、查询执行、结果导航和核心编辑流程。
- 焦点环、文本对比度和错误提示满足常见桌面可访问性要求。
- 空状态提供一个明确的下一步，不展示大段说明或多个竞争按钮。

## 17. 测试与质量策略

### 17.1 自动化测试

- 单元测试：查询切分、危险操作识别、数据类型转换、脱敏、状态恢复和命令注册。
- 适配器契约测试：四种数据库执行同一组共享能力测试。
- 集成测试：使用真实数据库容器验证连接、事务、取消、冲突、DDL、导入和导出。
- UI 测试：连接分区、强选中态、快捷键、标签上下文、简化 Loading、键盘导航和主题。

### 17.2 非功能测试

- 性能：冷启动、空闲内存、大 Schema、百万级结果流式浏览和大文件导出。
- 故障：网络中断、数据库重启、认证失效、磁盘空间不足、写入冲突和任务取消。
- 平台：Windows、macOS、Linux 的窗口、字体、快捷键、钥匙串和安装升级。
- 安全：凭据扫描、日志脱敏、生产环境确认和临时文件清理。

### 17.3 用户体验验收

- 新用户在 5 分钟内完成首次连接和查询。
- 用户无需说明即可完成查询、修改、复制和导出。
- 高频操作最多两次操作可达。
- 用户在任意查询标签中都能确认实际数据库上下文。
- 四种数据库共享操作习惯，同时保留原生能力。

## 18. 交付计划

排期假设为 3 名开发工程师和 1 名兼任产品设计/测试人员。四种数据库全部达到约定深度后再发布 1.0。

1. **基础工作台，5–7 周。** Tauri/React 壳、Rust 核心、本地存储、连接模型、标签、命令面板、任务调度和适配器接口。
2. **MySQL 与 PostgreSQL，8–10 周。** 关系型对象树、查询、事务、执行计划、数据编辑、表结构、DDL、索引和导入导出。
3. **MongoDB 与 Redis，8–10 周。** 文档查询、聚合管道、Schema 分析、Redis 数据结构、TTL、命令工作台和 Pub/Sub。
4. **产品化与公测，6–8 周。** 性能、崩溃恢复、快捷键、暗色模式、安装升级、跨平台兼容和交互打磨。

小团队整体预计 7–9 个月。单人开发的合理周期为 12–18 个月。

## 19. 1.0 发布门槛

- 四种数据库核心流程全部通过功能、契约和集成测试。
- 查询期间界面保持可响应且可取消。
- 生产连接不会被误切换，危险操作不会静默执行。
- 崩溃后可恢复工作区和未保存查询。
- 不存在凭据写入普通文件或日志的情况。
- 性能指标达到本设计规定的预算。
- 新用户无需外部说明即可完成连接、查询、修改、复制和导出。

## 20. 主要风险与处理

| 风险 | 处理方式 |
| --- | --- |
| 四种数据库能力差异导致界面割裂 | 固定共享操作语法，特有能力按适配器能力就近展示 |
| 首版范围过大 | 以四个内部里程碑交付，同一能力先完成共享契约再扩展适配器 |
| 大结果集导致内存和卡顿 | 流式协议、批次背压、结果虚拟化和后台导出 |
| 查询上下文误切换 | 标签锁定连接；对象树选择不隐式重绑定 |
| 写入造成数据损失 | Change Set、差异预览、事务或原生原子操作、冲突保护 |
| UI 随功能增加变重 | 高频入口固定、渐进披露、命令面板统一命令、每页一个主操作 |
| 本地历史泄露敏感信息 | 加密 SQLite、可关闭历史、日志脱敏和明确清理能力 |

## 21. 后续步骤

本设计经用户审阅确认后，再编写逐任务实施计划。实施计划必须先建立共享工作台与适配器契约，再按 MySQL、PostgreSQL、MongoDB、Redis 的内部里程碑推进；不得在设计确认前直接搭建功能代码。
